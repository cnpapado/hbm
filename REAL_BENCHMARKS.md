# Real-world benchmark circuits for the HBM evaluation

The paper's evaluation uses synthetic circuits (`scripts/generate_synth_bench.py`, `test/benchmarks_bursty_cx`).
This document describes the published and generated circuits collected as real-world counterparts:
where each one comes from, what state it is in, and how its T density was measured.

Everything here is at most 100 qubits. Circuits taken from published suites are kept **unmodified**, with the
step counts their authors chose.

Notes per family:

- **QUEST Heisenberg.** 1D chains of 4 and 8 qubits. Each Trotter bond is applied one at a time, which keeps the
  T density low (~0.3).
- **QED-C Heisenberg.** QED-C publishes a Qiskit generator, not QASM. `gen_qedc_heisenberg.py` transcribes the gate
  sequences of `hamiltonian_simulation_kernel.py` (method 1, default 3-CX `xxyyzz_opt_gate`) and uses the benchmark's
  own parameters from `_common/precalculated_data.json`: K = 5, t = 0.2, w = 1, published fields hx and hz.
  Each step applies field rotations to every qubit, then the interaction on even bonds, then on odd bonds.
  The n16 and n20 files are exactly what the benchmark builds. QED-C only publishes 20 field values, so for n25–n100
  the fields are cycled (`hx[i % 20]`); this is the only deviation. Final measurements are omitted.
- **QASMBench Ising.** Transverse-field Ising Trotter circuits laid out in brickwork. `ising_n10` is 5 steps; n26–n98
  are a single step. `ising_n10` names its register `reg`, which DASCOT cannot read (it only parses `q[...]`), so its
  register must be renamed before routing. `ising_n420` exists but is above the 100-qubit limit.
- **JKU Ising.** `ising_model_10` is the same circuit as QASMBench `ising_n10`; 13 and 16 are the same family.
  The AutoBraid copies (`autobraid/ising_model_*`) are **not** usable: their rotations were stripped, leaving only H and CX.
- **QUEST TFIM.** Generated by [f3c++](https://github.com/QuantumComputingLab/f3cpp), which compresses an entire
  time evolution into one fixed triangle of N(N−1)/2 two-qubit blocks. In `TFIM_step_k_N`, k is the simulated time
  step: the circuit structure is the same for every k, only the angles change. These circuits cannot be cut into
  individual Trotter steps. Many angles are tiny (10⁻⁶–10⁻³) and become free at coarse synthesis precision.
- **QAOA.** MaxCut on a random 3-regular graph (`networkx.random_regular_graph(3, n)`, **unseeded**, so rerunning
  `gen_qaoa.py` gives different graphs), all angles fixed at 1.0, converted to {rz, h, x, cx}. Edge terms are applied in
  networkx's edge order rather than in parallel layers, which limits density to ~0.3–0.4.
- **Fermi-Hubbard.** No published Fermi-Hubbard circuits remain once FTCircuitBench is excluded (its Hamiltonian
  circuits emit one Pauli term at a time, giving density 0.01–0.09), so `gen_fermi_hubbard.py` generates them:
  first-order Trotter, Jordan-Wigner encoding, t = 1, U = 4, dt = 0.1, one step. `parallel` groups bonds into layers
  with disjoint supports and puts both hopping rotations of a bond in one 2-CX gadget; `sequential` is the same
  Hamiltonian with one gadget per Pauli string, for comparison. `gen_fermi_hubbard.py --verify` checks every gadget
  against exact Pauli exponentials by statevector simulation.
- **Excluded.** FTCircuitBench (by decision), AutoBraid Ising (rotations stripped), anything above 100 qubits.

## 2. Synthesis to Clifford+T

DASCOT only routes `cx` and `t`/`tdg`, so rotations must be synthesized before routing.

**Done so far:** only QASMBench `ising_n26`, `n34`, `n66`, in
`quantum-compiler-benchmark-circuits/qasmbench_ising/clifford_t_eps1e-2/`, by `scripts/synth_ising.py`:

```bash
PYTHONPATH=wisq/src python scripts/synth_ising.py in.qasm out.qasm --eps 1e-2 --merge
```

It follows wisq's own path (`guoq.transpile_if_needed`):

1. translate to the NAM gate set {rz, h, x, cx} (so every `rx`/`ry` becomes an `rz` between Cliffords);
2. with `--merge`, fuse back-to-back `rz` on a qubit and drop `rz(0)` (lossless);
3. synthesize each `rz` with Qualtran's `diagonal_unitary_approx` (dps = 200, max T = 400), caching repeated angles.

Differences from running wisq directly: ε is **per rotation** (wisq splits a total budget as ε_total / (2·#rz));
measurements and barriers are dropped; a small shim adapts to the pinned Qualtran version. This is Qualtran's
synthesis, not gridsynth, but the T count per rotation follows the same ≈ 3·log₂(1/ε) scaling:

| ε per rotation | measured mean T per rotation |
|---|---|
| 1e-2 | ~20 |
| 1e-3 | ~31 |
| 1e-6 | ~62 |
| 1e-8 | ~82 |

**Everything else is still Clifford + rotations.** The T counts in section 4 are estimates (section 3). `synth_ising.py`
should work on any of the files above, since its first step translates every gate to the NAM basis.

Toffolis (`ccx`) are not synthesized by this path. For the arithmetic circuits, `t_density.py` expands each Toffoli
into 7 T gates (textbook decomposition by default, or a T-depth-3 form with `--toffoli tdepth3`); both
decompositions were checked against the exact Toffoli unitary.

## 3. How T density is calculated

`scripts/t_density.py` measures circuits **as DASCOT sees them**. DASCOT's `extract_gates_from_file`
(`wisq/src/wisq/dascot.py`) keeps only `cx` and `t`/`tdg`; every other gate is free and takes no timestep.

1. **Keep** only cx and T gates (after the rotation/Toffoli handling below).
2. **Schedule** them ASAP: each gate goes in the layer right after the latest layer used by any of its qubits.
3. **Measure:**

| Quantity | Definition |
|---|---|
| N | qubits touched by a cx or T (what DASCOT places on the grid) |
| L | number of layers, i.e. the cx/T depth (also the paper's cost-ratio denominator) |
| **density** | T / (N · L): fraction of qubit-layer slots that hold a T. 1.0 = every qubit does a T every layer |
| frac_T | fraction of layers with at least one T (the paper text's definition of P; ~1.0 for almost everything) |
| cong_avg | (mean T per layer that has a T) / 4√N: sustained demand over the 2D perimeter's magic-state supply |
| cong (peak) | (max T in one layer) / 4√N: worst single layer over the perimeter supply |

**Circuits that are not yet Clifford+T** (`--eps` or `--t-per-rotation`):

- `rz`, `rx`, `ry`, `u1`, `p`, and each Euler angle of `u2`/`u3`/`u` is one rotation.
- A rotation within ε of a multiple of π/2 (|sin(δ/2)| ≤ ε, δ = distance to the nearest multiple) is a Clifford: **free**.
- An odd multiple of π/4 is **1 T**.
- Any other angle is **K sequential T gates** on that qubit, K = ⌈3·log₂(1/ε)⌉ (20 at 10⁻², 80 at 10⁻⁸).
- `ccx`/`ccz` are expanded to 7 T as above.

Files whose register is not named `q` are marked `*`, since DASCOT would not see their gates.

**Check against real synthesis.** On the Clifford+T files the script matches its previous version exactly
(`bench_n100_p90`: density 0.485). The estimate for QASMBench Ising at `--eps 1e-2` (0.61–0.62) agrees with the actually
synthesized files (0.619–0.631) to within 0.02.

```bash
python scripts/t_density.py quantum-compiler-benchmark-circuits/qasmbench_ising/clifford_t_eps1e-2/*.qasm
python scripts/t_density.py --eps 1e-8 quantum-compiler-benchmark-circuits/qedc_heisenberg/*.qasm
python scripts/t_density.py --toffoli tdepth3 --csv out.csv quantum-compiler-benchmark-circuits/arithmetic/qcla_*.qasm
```

**Note on the paper's P.** The paper text defines P as "the fraction of circuit layers containing at least one
T gate", but `scripts/generate_synth_bench.py` uses P as the probability that *each qubit* gets a T in each layer.
Measured this way, the synthetic suite's density is 0.01–0.02 (P = 0.1), 0.11–0.13 (P = 0.5) and 0.41–0.49 (P = 0.9).
